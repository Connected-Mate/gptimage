# hoi4-imagegen

Use the `hoi4_imagegen` MCP (tools `hoi4.image_*`). It owns canvas sizes, alpha, margins, DDS or TGA export, naming, versions and provenance, and it runs the processing of every family itself: the report card with its vanilla-fitted shadow, the achievement triplet, the advisor card from the mod's template, the portrait crop with the bundled YuNet detector, the flag ladder, the focus `_shine` sprite, frame strips, and a flat opaque picture for the opaque families. Do not build a second image pipeline, do not run Python image tools by hand for an asset the tool makes, and do not write DDS files or sprite names by hand. HOI4 Mod Setup installs the binary and the project MCP entry. In the Agentic HOI4 Modding Kit, the `hoi4-feature-assets` skill keeps the source rules, naming and handoff rules this loop follows.

## Tools
* `hoi4.image_status`, `hoi4.image_families` (the catalogue: every family's measured spec, the mod's override, its style sources), `hoi4.image_references`.
* Six generation tools, one per group, each with a **required** `family` that the schema checks: `hoi4.image_icon`, `hoi4.image_picture`, `hoi4.image_portrait`, `hoi4.image_flag`, `hoi4.image_unit`, `hoi4.image_interface`. Without `approve` they return a free plan. With `approve: true` and an `idempotency_key` they generate.
* `hoi4.image_generate`, `hoi4.image_edit`, `hoi4.image_process`, `hoi4.image_validate`, `hoi4.image_preview`, `hoi4.image_review`, `hoi4.image_install`, `hoi4.image_ledger`, `hoi4.image_cancel`.
* `hoi4.image_audit` audits the whole mod for cross-family reuse, missing textures, missing focus shine and wrong canvases. Run it before a release or after importing art. Existing reuse is a warning; add intended aliases to `.hoi4-imagegen/audit-allowlist.json`.
* `hoi4.image_set` plans every icon of one focus tree file as one set (`focus_tree`: the file in the mod): one `focus` asset per distinct sprite, briefs from the focus names, and the same style pack, anchors, provider and quality for all. Generate one icon first, approve it and pass it as a `style_anchor`, then run the set with `generate: true` and an `idempotency_key`. Point a focus's `icon` at the reply's `installs_as` where `tree_names_it` is false.

## The 45 families
* Icon group (`hoi4.image_icon`): `focus`, `idea_spirit`, `idea_concern`, `officer_corps_spirit`, `decision` (also missions), `decision_category_icon`, `state_modifier` (also dynamic modifiers), `special_project_icon`, `raid`, `mio_department`, `mio_trait`, `mio_policy`, `bop_side`, `medal`, `agency_upgrade`, `operation_icon`, `commander_trait`, `personal_trait`, `doctrine`.
* Picture group (`hoi4.image_picture`): `report_event`, `news_event`, `decision_category_picture`, `operation_picture`, `technology`, `achievement`.
* Portrait group (`hoi4.image_portrait`): `leader_portrait`, `commander_portrait`, `operative_portrait`, `scientist_portrait`, `advisor_card`.
* Flag (`hoi4.image_flag`): `flag`.
* Unit group (`hoi4.image_unit`): `counter_large`, `counter_small`, `division_emblem`, `building`, `faction_logo`, `agency_logo`.
* Interface group (`hoi4.image_interface`): `modifier_stat_icon`, `gui_texture`, `super_event`, and `model_reference`, which is not game art: the input picture of an image-to-3D tool such as Tripo or Meshy (one whole subject facing the camera on a plain light grey backdrop or real alpha, your canvas, your own references only, see "Model references" below). It is processed and validated, and install refuses it: use the PNG.
* Animation group (`hoi4.image_animation`): `anim_blend_glow`, `anim_blend_keyframes`, `anim_scroll`, `anim_spin`. One base frame is generated and the other frames are derived from it.

## When not to use it
* Animation beyond a frame strip, and 3D models, rigs and exports, apart from their input picture (`model_reference`) (the kit has `hoi4-frame-animation` and `hoi4-3d-model-pipeline` for these). Bring a finished frame strip under the ledger with `hoi4.image_process` and `import`.
* Sourced and user-provided art of one of the 45 families is not generated, but it is imported with `hoi4.image_process` (a required `family`) so its crop, validation, review and install run under the same ledger. An image of another family's size, or the pixels of an installed asset of another family, is refused.
* Real people. A real identity should use an attributed source, imported through `hoi4.image_process`, never a generated likeness (the kit's `hoi4-feature-assets` decides this first). Only wholly fictional identities are generated. Providers may refuse or treat differently images of real people, the Steam warranty covers personal rights, and the project may forbid a category outright.
* Art that is not one of the 45 families has no route here.

## Providers
* The ChatGPT login is the default local provider once you have run `hoi4-imagegen login` (a browser sign-in and a one-time risk note). Every image runs on gpt-6-luna at high reasoning effort, and the route refuses a response whose model or effort differs. The backend's own image tool chooses the quality and size, which the route cannot force, so check the pixels. It calls an undocumented backend that OpenAI does not support for other tools, and it is never part of a hosted deployment.
* Documented providers stay available: `OPENAI_API_KEY`, `GEMINI_API_KEY` (or `GOOGLE_API_KEY`), `FAL_KEY`, and a ComfyUI endpoint. Keys come from the environment, or from HOI4 Mod Setup's credential store when the variable is not set: never type one into chat, a file or a command. A plan with an explicit `provider` wins over the default.

## The loop (one asset at a time)
1. `hoi4.image_status`. Check that a provider is signed in or has its key, and that the model is not retired or deprecated.
2. `hoi4.image_families { family }`. Read the group (it names the tool), the canvas, margin, evidence, review questions, and the style sources with the reason each was chosen. The canvas is the mod's profile (`.tools/gfx/profiles.json`), vanilla by default. A canvas that differs from the vanilla default is a project choice: say so.
3. References first. Style references come from the mod first (its copy of the asset skill's `assets/` folder and its existing assets of that family) and from the vanilla shelf second, and the tool reports which it used and why. Vanilla references may always be sent to a provider when they help, so no flag is needed. The automatic set depends on the brief: it leaves out nation-specific art unless the brief names the country, draws from the brief's sub-family (or the one you name with `subfamily`) and varies per brief. Your own `style_anchor` references replace every automatic one, unless you pass `style_mode: "add"`. A `GFX-NEAR-DUPLICATE` warning means the output repeats an earlier one's frame and composition. Add approved images with `hoi4.image_references` (role and rights note) and save a style with `style_save`. A mod with its own house style across many families uses a style pack (`pack_list`, `pack_get`, `pack_save`, `pack_validate`, or `hoi4-imagegen pack import`). Make one from a mod's own art with `pack_derive` (`from_mod`: the mod folder, or `hoi4-imagegen pack derive <name> --from-mod <folder>`), then open each family's contact sheet and swap out any pick that shows an extremist symbol, a recognisable real person or a placeholder (`swap: ["focus:3=a2"]`, `replace: true`): the measurement cannot see those. Name the pack in a plan with `style_pack`, or set `[defaults] style_pack`. The pack's references then count as your own anchors, and your own `style_anchor` references still win over them. Read `style_pack` in the plan to see which entry applied. Roles: `style_anchor`, `subject_anchor`, `geometry_anchor`. Never invent a source: ask the user for references when style matters.
4. The group tool with a `family`. Without `approve` it is the free plan. Read the estimate, its basis, the warnings and `approvals`, and tell the user the cost before generating. A plan with the same inputs gives the same id. The family is fixed from here on: an idea icon is never a focus or decision icon, and the tool refuses to treat it as one.
5. Call the group tool again with `approve: true` and an `idempotency_key` (or `hoi4.image_generate { plan_id, idempotency_key }`). One asset per call. Reuse the key when retrying: it replays instead of paying again. After an error with retry class `reconcile_first`, use `hoi4.image_cancel` with `reconcile` and never retry blindly.
6. `hoi4.image_process { candidate_id }`. The deterministic fit for the family. If it says `no_transparency_in_source`, the provider returned an opaque picture: regenerate with a model that has native alpha, or use a matte workflow only when the background is one flat colour. Counters and division symbols are different: the model draws one solid black silhouette on plain white, and processing renders vanilla's green or grey look and, for counters, the NATO box. Pass `counter_symbol` (a preset such as `medium_armor` or `infantry+support`, or marks such as `cross+wheels`) when the sub-unit key does not say which symbol it needs. The result reports the symbol it used.
7. `hoi4.image_validate { targets: [artifact] }`. The artifact's own family and its full check set always apply. Fix errors, then validate again. A pass is geometry only.
8. `hoi4.image_preview`. Look at the native-size panels first, then at the second sheet: the candidate beside the family's vanilla references. Read `vanilla_check` in the reply.
9. `hoi4.image_review`. The v3 questions are asked against the vanilla references. Answer every one honestly. The first, `shows_brief_subject`, asks whether the image shows what the brief asks for: no measured check can judge that, so look at the image against the brief the reply quotes. The review also measures the file against vanilla itself and refuses an approval that does not match (`review_vanilla_mismatch` names the features). Approve only if all answers are true, otherwise `changes_requested`, then `hoi4.image_edit` with a precise instruction and go back to step 6. Use `override_vanilla_check` with an `override_reason` only for a deliberate mod style the user asked for.
10. `hoi4.image_install { target, approval_id }`. The default `mode: handoff` writes the sprite into `docs/assets/<feature>/gfx_handoff.md`, and the main agent wires `.gfx`. The result's `script` field (also in the handoff as "In script") is what the mod's script must say for the game to find the art, for example `picture = <asset>` for an idea, or "name the sub-unit `<asset>`" for a counter. For families whose sprite the game builds from a key (ideas, decisions, traits, technologies, sub-units, raid types), choose the asset name to be that key.
11. When the feature is done, list in the handoff every asset installed and any `GFX-STYLE-DRIFT` warning.

## Model references (input for image-to-3D)
`model_reference` makes the picture an image-to-3D tool such as Tripo or Meshy turns into a model. The family's rules already ask for one whole subject facing the camera in a neutral pose, arms out in a slight A-pose with backdrop under each arm, legs a little apart, held items gripped in a closed hand and clear of the body, believable anatomy and materials (not a cartoon or toy, not a too-clean CG render), a non-human subject's own anatomy and face, defining features at the size the reference shows, and every detail of the subject's reference kept with nothing invented. Do not repeat those in the brief. Describe the subject.
* Backdrop: `grey` (the default, a plain light grey picture) or `backdrop: "transparent"` for real alpha. The transparent one is processed with the `cutout` recipe (solid subject, clear surround, and a subject that touches the edge is fitted again with a 5 percent margin) and checked with `alpha_border`. `no_transparency_in_source` or a `GFX-MODEL-ALPHA` error means the backend fell back to a backdrop: generate again, or use grey. On grey, check the margin yourself: a tip near the edge cannot be refitted on an opaque picture.
* Size features by body landmarks ("the blade reaches from the hip to the ground", "the wings span twice the body's height"). The image model ignores numeric ratios.
* Pass the whole drawing page as a `subject_anchor` when it holds detail studies (the head, a weapon, markings), not a crop of the main figure, so no detail is lost.
* To fix an approved picture, pass it as the first reference (`subject_anchor`) and change one thing in the brief ("keep everything, only straighten the left arm"). Several changes at once drift elsewhere.
* Keep the brief under 4000 characters (the plan refuses a longer one). Cut repetition of the family's rules first.
* Review with `interface_model_v4`: pose, believable anatomy, feature scale and faithfulness to the reference are questions of their own. Look at the picture next to the subject's reference before you answer them.

## What it refuses (and why)
* Install without a passing validation, an approving review of the exact file, and unchanged hashes (file, raw candidate, plan).
* Overwriting any file it did not install. Pick a new asset name.
* Retired models, unknown models, extra references a model cannot take, and keys sent to unlisted hosts.
* Using one family's asset as another's: `GFX-FAMILY-MISMATCH` (the size belongs to another family) and `GFX-FAMILY-REUSE` (the same pixels are already installed for another family).
* Enlarging an icon more than 1.25 times.
* Fake transparency: an opaque result, or a drawn grey and white checkerboard.

## Where things land
`docs/assets/<feature>/source_png|processed_png|prompts|contact_sheets`, finals in the kit's feature-scoped folders (for example `gfx/interface/goals/<feature>/focus_<asset>.dds`), state in `.hoi4-imagegen/` (config, styles, plans, `ledger.jsonl`, records). Names are lowercase snake_case, and flags use the country tag.

## Facts to keep straight
* Canvas sizes are the mod's profile, vanilla by default (HOI4 1.19.4.1): focus 100x88, idea_spirit 60x68, idea_concern 64x64, advisor_card 65x67, decision 33x32, report 210x176, news 397x153 (black and white), flags 82x52, 41x26 and 10x7. In the kit, `CATALOG.md` in the vanilla shelf lists the canvas of every family. A mod that settled other sizes lists them in its own `.tools/gfx/profiles.json` rows, and `hoi4.image_families` then shows the override next to the vanilla value. `gui_texture` and `super_event` have no vanilla canvas, so the mod defines them.
* Focus icons have a paired `_shine` sprite in vanilla. The handoff includes one, marked "pattern observed, game behaviour untested". Do not claim it is required.
* No text in art. Generated text is always wrong.
* In-game appearance is user-operated evidence this tool cannot give. Say "installed", not "verified in game".
* Never start Hearts of Iron IV to check an asset. List exactly what the user should look at in game.
